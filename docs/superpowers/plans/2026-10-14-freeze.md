# Freeze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-knob granular VST3/Standalone effect, "Freeze" by fouren, that turns a pluck rhythm into one sustained sound, buildable and audible on a Mac with no DAW and no admin rights.

**Architecture:** A JUCE-free C++17 DSP core (`FreezeEngine`: gated capture buffer + granular cloud + equal-power mix) unit-tested by a tiny in-repo test harness. A thin JUCE wrapper (processor + one-knob editor) builds VST3 + Standalone. Offline `render` and `snapshot` tools let you hear and see it without a DAW; GitHub Actions builds Windows.

**Tech Stack:** C++17, JUCE 8.0.15, CMake + Ninja from a Python venv, CTest, GitHub Actions, pluginval v1.0.4.

**Spec:** `docs/superpowers/specs/2026-10-14-freeze-design.md`

## Global Constraints

- No code, assets or files copied from any other plugin project.
- No admin rights: toolchain in `.venv/`, JUCE in `external/JUCE`, VST3 copied to `~/Library/Audio/Plug-Ins/VST3` (macOS only).
- C++17; `CMAKE_OSX_DEPLOYMENT_TARGET` 11.0.
- JUCE tag `8.0.15`.
- Product "Freeze", company "fouren", manufacturer code `Fren`, plugin code `Frz1`, bundle id `com.fouren.freeze`, CMake target `Freeze`, formats `VST3 Standalone`.
- CMake option `GF_BUILD_PLUGIN` (default ON) gates everything that needs JUCE; the DSP lib and tests never depend on JUCE.
- One parameter, id `freeze`, 0..1, default 0, shown as 0–100 %, 50 ms linear smoothing.
- Latency 0. No allocation, locks or I/O in `process` / `processBlock`.
- Buses: mono→mono and stereo→stereo only.
- UI title text is exactly "Freeze"; knob label "Freeze".

## Review Focus

1. **Host block larger than `prepareToPlay`'s size** — must still work: the processor processes in chunks of at most the prepared size (test in Task 4).
2. **Sample rate other than 48 kHz (44.1/96 kHz)** — all times (10 ms, 20 ms, 120 ms, 1 s, 2 s) are converted from seconds, so the gap-filling test must also pass at 44.1 kHz and 96 kHz (test in Task 3).
3. **Knob raised after a long time at 0** — capture keeps running at 0, so wet output appears immediately when raised (test in Task 3).
4. **Very loud / DC input** — no NaN, no runaway level: covered by the stability test; add a full-scale square-wave case (Task 3).
5. **Mono plugin instance** — engine prepared with 1 channel must run and fill gaps (test in Task 3).

### Task 2: PRNG and gated capture buffer

**Files:**
- Create: `source/dsp/Random.h`, `source/dsp/FreezeEngine.h`, `source/dsp/FreezeEngine.cpp`
- Create: `tests/Signals.h`, `tests/test_capture.cpp`

**Interfaces:**
- Produces (`namespace gf`):
  - `class Random { explicit Random(uint64_t seed = 1); void seed(uint64_t); uint64_t next(); double uniform(); /* [0,1) */ int below(int n); /* [0,n) */ }` — xoshiro256** seeded via splitmix64.
  - `class FreezeEngine` with:
    - `void prepare(double sampleRate, int maxBlockSize, int numChannels);` (numChannels 1 or 2)
    - `void reset();`
    - `void setSeed(uint64_t);`
    - `void process(float* const* channels, int numChannels, int numSamples, const float* freezeAmount);`
    - `int64_t recordedSamples(int channel) const;` — total samples committed to the capture buffer so far (test/diagnostic accessor).
  - `tests/Signals.h` (header-only, JUCE-free): `std::vector<float> pluckTrain(double sr, double seconds, double freqHz = 220, double plucksPerSec = 4, float amp = 0.5f, double tau = 0.025);` (sine × `amp·exp(-t/tau)`, hard zero after 200 ms of each pluck); `std::vector<float> sine(double sr, double seconds, double freqHz, float amp);` `double rms(const float*, size_t n);` `std::vector<std::vector<float>> runEngine(gf::FreezeEngine&, std::vector<std::vector<float>> input, const std::vector<float>& amount, int blockSize);` (processes in blocks, returns output per channel).

Capture algorithm (the part the tests pin): segment length `S = round(0.010·sr)`. Each channel keeps a staging array of `S` samples filled on an absolute sample counter (boundaries at multiples of `S` since `reset`). When a segment completes, compute its RMS; if `RMS ≥ 0.001` (−60 dBFS) append the `S` samples to the 2 s circular buffer (capacity rounded to whole segments) and push the RMS into a circular energy table (one entry per buffer segment); otherwise drop it. Capture always runs, whatever the amount. In this task `process` leaves the audio untouched.

### Task 3: Grain cloud and mix

**Files:**
- Modify: `source/dsp/FreezeEngine.h`, `source/dsp/FreezeEngine.cpp`
- Create: `tests/test_freeze.cpp`

**Interfaces:**
- Consumes: Task 2's `FreezeEngine`, `Random`, `tests/Signals.h`.
- Produces: final `FreezeEngine::process` behaviour (signature unchanged). Constants in `FreezeEngine.h` (namespace `gf`): `kGrainSeconds = 0.120`, `kSpawnSeconds = 0.020`, `kSpawnJitter = 0.25`, `kMaxGrains = 16`, `kSelectSeconds = 1.0`, `kSelectThreshold = 0.25f`, `kSilenceRms = 0.001f`, `kBufferSeconds = 2.0`, `kSegmentSeconds = 0.010`, `kWetGain = 1 / sqrt((kGrainSeconds / kSpawnSeconds) · 0.375)` (= 0.6667).

Grain algorithm (per channel, each with its own `Random` seeded from `seed + channel`):
- Spawn times on the absolute sample counter: next spawn = previous + `round(kSpawnSeconds·sr·(1 + kSpawnJitter·(2u−1)))`.
- On spawn, eligible segments = committed segments within the last `kSelectSeconds` of committed material, excluding the newest `ceil(kGrainSeconds / kSegmentSeconds)` segments (so start + grain length ≤ write head), whose RMS ≥ `kSelectThreshold ×` max RMS among them. Pick one uniformly, start at a uniform offset inside it. If fewer than `grainLength` samples are committed, spawn nothing. If all 16 voices are busy, replace the one with the most samples played.
- A grain reads `grainLength = round(kGrainSeconds·sr)` consecutive samples from its start at original pitch, multiplied by Hann `0.5 − 0.5·cos(2π·i/(L−1))`.
- `wet = kWetGain · Σ grains`; `out = in·cos(k·π/2) + wet·sin(k·π/2)`, `k = freezeAmount[i]`.
- If every `freezeAmount` in the block is 0: capture only, clear active grains, set next spawn to the current sample, leave the audio untouched.
